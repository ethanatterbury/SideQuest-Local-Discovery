# Optional national place discovery

SideQuest uses Geoapify's Free Places API when the server has `GEOAPIFY_API_KEY`. Create a Free project at [Geoapify MyProjects](https://myprojects.geoapify.com/), add its key to that variable in Vercel's **Production** environment, then deploy. For local development, put it in `.env.local` and restart Next. The key must have no `NEXT_PUBLIC_` prefix; browsers call SideQuest's API and never receive it. Leave the variable blank to retain regional snapshots and best-effort Overpass discovery.

The [official Places documentation](https://apidocs.geoapify.com/docs/places/) describes a Free allowance of 3,000 credits per day, with one credit per 20 returned places. A full uncached search here returns at most 300 activity candidates, 100 catering candidates and 100 commercial candidates, so it can consume up to 25 credits. Detail requests normally cost one credit. Use the Free plan without adding payment details; this implementation does not activate billing or upgrade plans. Watch usage in the provider dashboard: this is an allowance for a modest deployment, not unlimited public traffic.

`/api/places` makes three concurrent circle searches with separate activity, catering and commercial budgets, proximity bias, and a shared 2.5-second deadline. The activity search requests entertainment, leisure, natural, sport and tourism; catering and commercial places cannot consume its result budget. Results are deduplicated, passed through the existing OSM normalization and shared eligibility rules, and capped at 300 nearby candidates. Mapped indoor play, restrictions, age bounds and media references survive conversion. Names and Geoapify categories never establish infant suitability. Unsupported infrastructure, private access and closed facilities are excluded.

Successful areas are cached for 30 minutes in each server instance and concurrent requests share work. Failed areas wait 60 seconds before retrying. Authentication and rate-limit responses also pause Geoapify requests across areas for 60 seconds in that instance. A successful activity batch survives an optional-batch failure; failed or empty activity batches merge the existing outing fallback while retaining optional results. Every Geoapify-degraded fallback is marked incomplete even when the fallback source is cached/live; the message marks this partial coverage and its server cache lasts one minute. When neither batch supplies usable local places, empty, invalid and timed-out responses fall back to existing Overpass/regional/curated data with explicit source messages. Successful API responses can also be cached at the CDN for 30 minutes; fallback and partial responses use a one-minute CDN lifetime. These bounds reduce requests but are not a distributed quota enforcement service. Present country codes must identify Great Britain; the provider's unsupported country search filter is not used.

Stable `osm-node-*`, `osm-way-*` and `osm-relation-*` IDs preserve saved places and plans. Newly fetched places enter the existing bounded detail registry. After a server cold start, `/api/places/[id]` can retrieve the exact OSM object with [Geoapify's documented `osm_id` and `osm_type` lookup](https://apidocs.geoapify.com/how-to/place-discovery/place-details-by-id-or-coordinates); the existing snapshot/Overpass lookup remains the fallback. Upstream outages can still leave an uncached detail temporarily unavailable. Recent browser areas retain the normalized source record and Geoapify attribution through reloads.

Place results show Geoapify and © OpenStreetMap contributors attribution. Geoapify supplies listings here, **not venue photographs**. Optional raw OSM and `wiki_and_media` references only feed the existing photograph identity and rights checks; they do not create a licensed photo or imply every venue has one. There is no national photo warehouse.

To check deployment, request `/api/places?lat=53.48&lng=-2.24&radius=10&refresh=1` and another location outside the regional snapshot, then inspect `source`, `message`, returned OSM IDs and a direct `/api/places/{id}` response. `live` or `cached` with the Geoapify message establishes a provider result for that area; a fallback message does not. Automated tests use documented response fixtures and simulate error conditions. Runtime coverage must be checked against the deployed, configured provider before claiming national coverage.
