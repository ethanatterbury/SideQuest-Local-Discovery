# SideQuest v1 design

The uploaded brief is binding. Build Next.js App Router with server layout and static public place routes around focused client feature boundaries. Domain functions consume normalized Place, Environment, DiscoveryQuery and local preference models. Curated content includes source links, editorial duration, unknown factual hours/prices, independently licensed images where available.
Providers: curated places; Open-Meteo current/hourly/daily weather with validation, timeout and cache; estimated routing with rounding; no-key geocoding with preset towns and coordinate fallback; safe local JSON persistence with versioned schemas and storage failure handling. Precise device coordinates remain in memory.
Core flow: starting location → one mood → 3–5 ranked options. Escape and novelty modes return one ranked eligible option with explainable facts. Plan mode creates geographically constrained stops with round-trip travel, daylight, budget and duration limits; food is a user-budgeted break rather than invented venue availability.
Navigation: Discover, Explore, Map, Saved, Been there. Place pages support save, dismiss, visit reaction/note, share and platform directions. Collections and explicit history persist locally. Share URLs preserve query or itinerary IDs/time. No account, database, reviews, crowds or fabricated events.
Map: lazy MapLibre adapter, clustered GeoJSON, selected markers, radius, route line explicitly estimated, saved/visited state, mobile sheet and gesture. Tile/WebGL failure yields an honest coordinate overview and list.
Environment Lab: private /dev/environment route and keyboard control in development/explicit preview; centralized context controls weather, time, sliders, locations, failures, device width and motion; ranking debug. Hidden production route returns 404.
PWA: manifest, PNG icons, service-worker static/navigation cache, offline page and retained local content. Small typography bundles and image dimensions prevent layout shift. HTTP weather errors never block discovery.
Verification: domain tests first; scoring, opening/time windows, travel, parsing, persistence, override and itinerary constraints. Playwright critical flow tests plus representative viewport and environment screenshots. Typecheck, ESLint, tests, production build. README must disclose dataset freshness, estimated routing, map/data provider production requirements and future cloud migration.
